# 文档

这个目录只放三类东西：

- **架构定义** —— 引擎由哪些部件构成、部件之间的契约
- **设计** —— 某个机制为什么这样设计、边界条件在哪
- **流程** —— 构建、部署、启动、排障的操作顺序

不放调查记录、草稿、一次性分析、复盘。那些属于过程，不属于文档。

## 实测记录（2026-11-09 追加）

上面那条规矩（「不放调查记录」）是 2026-11-09 之前定的。当天做了一整天的性能与
正确性排查，产出的一批文件**确实属于「过程」而不是「文档」**，但删掉会让下一个人
把同样的实验重做一遍（那天就有八条假设被反复验证过，每条都花了半小时以上）。

所以保留它们，但单独归类，并**明确它们不是权威设计文档**：写的是「某天在某台
机器上观察到什么」，不是「系统应该怎样」。

| 文件 | 性质 |
| --- | --- |
| [未解决-不确定性.md](未解决-不确定性.md) | **最重要的一份。** forward 结果不确定的完整排查链、八条被排除的假设、最终结论（槽位/显存余量）与待办。接手先读这个。 |
| [幽灵开关.md](幽灵开关.md) | 环境变量设了不生效的一类 bug，含一次误判与纠正。 |
| [解量化开销.md](解量化开销.md) | `wo_a` 是 fp8、计算前先解成 bf16 的开销，以及 dequant 快路径的对齐 bug。 |
| [性能结构.md](性能结构.md) | 一次 decode step 的时间分布与测量方法。 |
| [性能波动.md](性能波动.md) | 「配置在跳」和「环境在抖」怎么分开。 |
| [内存取舍.md](内存取舍.md) | 一次被数据推翻的「省内存」优化，记录了为什么反直觉。 |
| [预热.md](预热.md) | 预热深度如何决定测出来的数字。 |

配套脚本：`scripts/diag_nan.py` —— 统计 forward 的 NaN 率，支持按环境变量分组
对比。**判断任何改动是否修好概率性 bug，至少跑 8~10 次并对照基线**（那天被小样本
骗过两次）。
