# tinyinfer OpenAI 兼容 API

tinyinfer 的对外服务层：把后端（Mock 或真实引擎）包装成 OpenAI 兼容的 HTTP API，供一个或几个 agent 并发调用。
后端只负责生成 token，服务层负责协议、SSE、usage、错误格式、request id、API key、限流、超时和会话槽位。

- 代码：`tinyinfer/src/tinyinfer/server.py`（FastAPI 应用）、`tinyinfer/src/tinyinfer/cli.py`（`serve` 子命令）
- 依赖：`pyproject.toml` 的 `server` extra（fastapi、uvicorn、httpx）

---

## 1. 启动

在仓库根目录执行：

```powershell
# Mock 后端，不需要模型权重
.\tinyinfer\.venv\Scripts\python.exe -m tinyinfer.server --backend mock --port 8000

# 等价写法
.\tinyinfer\.venv\Scripts\python.exe -m tinyinfer.cli serve --backend mock --port 8000

# 健康检查
.\tinyinfer\.venv\Scripts\python.exe -c "import httpx; print(httpx.get('http://127.0.0.1:8000/health').json())"
```

`src` 不在解释器路径里时补一句 `$env:PYTHONPATH = ".\tinyinfer\src"`。

服务默认监听 `127.0.0.1:8000`，交互式文档在 `/docs`，OpenAPI 在 `/openapi.json`。

启动参数（`--help` 可看全量）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--host` / `--port` | `127.0.0.1` / `8000` | 监听地址与端口 |
| `--backend` | `mock` | `mock` 或 `tiny` |
| `--model-dir` | 无 | 默认模型的 HF safetensors 目录，需含 `config.json` 与 `model.safetensors.index.json`；`--backend tiny` 时与 `--extra-model` 至少给一个 |
| `--extra-model NAME=DIR` | 无 | 注册额外模型，可重复；多模型时按请求的 `model` 路由 |
| `--model-id` | 目录名 | 默认模型对外暴露的 id |
| `--default-model` | 第一个注册的模型 | 请求里的 `model` 未匹配任何 id 或别名时落到哪个模型 |
| `--layers` | 全部层 | 逗号分隔的层号，做分段加载用，如 `--layers 0` |
| `--device` | `auto` | `auto` / `cpu` / `cuda` |
| `--adapter` | `auto` | `auto` / `hf_deepseek_v41` / `gguf`（GGUF 为预留，调用返回 501） |
| `--tier` | `aggressive` | 后端优化档位：`conservative` / `balanced` / `aggressive`；`extreme` 未实现，启动即报错 |
| `--api-key` | 无 | 逗号分隔多个 key；也读环境变量 `TINYINFER_API_KEY` |
| `--max-concurrency` | `4` | 同时在跑的 HTTP 请求数，超过返回 429 |
| `--max-slots` | `4` | 会话槽位数，即 KV / 专家缓存的归属单位 |
| `--max-context-tokens` | `1048576`（1M） | 上下文上限 |
| `--max-tokens-limit` | `1048576` | 单次输出上限 |
| `--default-max-tokens` | `256` | 请求没带 `max_tokens` 时的默认值 |
| `--fit-max-tokens` | 关 | 超上下文时把 `max_tokens` 压到剩余空间，而不是返回 400 |
| `--request-timeout` | `600` | 单请求超时（秒）；超时返回 504，流式中以 error 帧上报 |
| `--sse-keepalive` | `15` | 流式 keep-alive 注释间隔（秒），0 为关闭 |
| `--log-level` | `info` | `debug` / `info` / `warning` / `error` |

## 2. 端点

## 3. 认证与请求标识

- 配置了 `--api-key` 后，所有 `/v1/*` 与 `/slots` 都要求 `Authorization: Bearer <key>`；`/health` 保持公开。
  多个 key 用逗号分隔，任一匹配即可。未带或带错返回 401 `invalid_api_key`，响应头含 `WWW-Authenticate: Bearer`。
- `/docs` 与 `/openapi.json` 不受 API key 保护，对外暴露前自行决定是否关闭。
- 每个响应都带 `x-request-id`：请求头传了就原样回显（超 128 字符截断），否则生成 `req_<hex>`。
- 带了 `session_id` 的请求，响应头额外回显 `x-session-id`。
- 流式响应同样是先回响应头，再回 SSE 数据。

```powershell
curl.exe http://127.0.0.1:8000/v1/models -H "Authorization: Bearer sk-demo"
```

## 4. 文本补全 `/v1/completions`

### 4.1 请求字段

| 字段 | 类型 | 约束 |
|---|---|---|
| `prompt` | 字符串或字符串列表 | 必填；列表只允许单元素，多元素返回 400；空字符串允许 |
| `model` | 字符串 | 任意名字都接受，响应原样回显；未匹配已注册模型时路由到默认模型 |
| `max_tokens` | 整数 | ≥1，且不超过 `--max-tokens-limit`；缺省取 `--default-max-tokens` |
| `temperature` | 浮点 | 0–2 |
| `top_p` | 浮点 | (0, 1] |
| `top_k` | 整数 | ≥0，0 表示不截断（扩展字段） |
| `presence_penalty` | 浮点 | −2–2 |
| `repetition_penalty` | 浮点 | >0（扩展字段） |
| `stop` | 字符串或字符串列表 | 最多 4 个，元素必须非空 |
| `seed` | 整数 | 可选 |
| `n` | 整数 | 只支持 1，其它值返回 400 |
| `stream` | 布尔 | 是否走 SSE |
| `stream_options.include_usage` | 布尔 | 流式时是否追加一帧 usage |
| `session_id` | 字符串 | 扩展字段，见第 6 节 |
| `echo` / `logprobs` / `suffix` / `user` | — | 接受但不生效，保持请求可解析 |

### 4.2 非流式

```powershell
curl.exe http://127.0.0.1:8000/v1/completions `
  -H "Content-Type: application/json" `
  -d '{"model":"tinyinfer-mock","prompt":"hello tiny world","max_tokens":8,"temperature":0,"seed":7}'
```

响应（节选）：

```json
{
  "id": "cmpl-4f8c...",
  "object": "text_completion",
  "created": 1792512960,
  "model": "tinyinfer-mock",
  "choices": [
    {"index": 0, "text": "echo: hello tiny world edge memory", "logprobs": null, "finish_reason": "length"}
  ],
  "usage": {"prompt_tokens": 3, "completion_tokens": 8, "total_tokens": 11}
}
```

| 字段 | 说明 |
|---|---|
| `id` | `cmpl-<hex>` |
| `object` | 固定 `text_completion`（流式帧同样是这个值） |
| `created` | Unix 秒 |
| `model` | 回显请求里的 `model`；请求没带则用后端默认 id |
| `choices[].text` | 生成文本 |
| `choices[].logprobs` | 固定 `null` |
| `choices[].finish_reason` | `stop`（命中 stop 或 EOS）或 `length`（到 `max_tokens`） |
| `usage` | prompt / completion / total 三项 token 数 |

### 4.3 流式

```powershell
curl.exe -N http://127.0.0.1:8000/v1/completions `
  -H "Content-Type: application/json" `
  -d '{"prompt":"stream me","max_tokens":6,"stream":true,"stream_options":{"include_usage":true}}'
```

```text
data: {"id":"cmpl-...","object":"text_completion","created":...,"model":"tinyinfer-mock","choices":[{"index":0,"text":"","logprobs":null,"finish_reason":null}]}

data: {"id":"cmpl-...","object":"text_completion",...,"choices":[{"index":0,"text":"echo:","logprobs":null,"finish_reason":null}]}

: keep-alive

data: {"id":"cmpl-...","object":"text_completion",...,"choices":[{"index":0,"text":"","logprobs":null,"finish_reason":"length"}]}

data: {"id":"cmpl-...","object":"text_completion",...,"choices":[],"usage":{"prompt_tokens":2,"completion_tokens":6,"total_tokens":8}}

data: [DONE]
```

- 一行一个 `data:` 帧，帧之间空行分隔；结束固定 `data: [DONE]`。
- 每帧都是完整的 JSON 片段，客户端按行取 `data: ` 之后的部分解析即可。
- 第一帧的 `text` 为空串，之后每帧带一个增量文本片段；最后一帧 `choices[0].text` 为空、`finish_reason` 有值。
- 服务端读长 prompt 期间会发 `: keep-alive` 注释（SSE 注释，客户端应忽略），避免 agent 侧超时。
- `stream_options.include_usage=true` 时，finish 帧之后多一帧 `choices: []` + `usage`。

## 5. 聊天补全 `/v1/chat/completions`

### 5.1 请求字段

除下列字段外，其余采样字段与 4.1 完全一致（`prompt` 除外）：

| 字段 | 类型 | 约束 |
|---|---|---|
| `messages` | 消息数组 | 必填，至少一条，且所有消息内容拼起来不能为空串，否则 400 |
| `messages[].role` | 字符串 | `system` / `user` / `assistant` / `tool` / `developer` / `function` |
| `messages[].content` | 字符串或分片数组 | 文本分片形如 `[{"type":"text","text":"..."}]`，也接受 `input_text`；图片等非文本分片返回 400 |
| `messages[].name` / `tool_call_id` / `tool_calls` | 可选 | 原样透传给后端渲染 |
| `max_completion_tokens` | 整数 | 与 `max_tokens` 等价，同时给时以 `max_tokens` 为准 |
| `tools` | 数组 | 声明可用的函数，用于最小 function calling 回显，见 5.4 |
| `tool_choice` | 字符串或对象 | 传 `"none"` 关闭 tool 识别 |
| `parallel_tool_calls` | 布尔 | 接受但不处理，始终只回显一个调用 |
| `response_format` | 对象 | 接受但不生效 |

### 5.2 非流式

```powershell
curl.exe http://127.0.0.1:8000/v1/chat/completions `
  -H "Content-Type: application/json" `
  -d '{"model":"tinyinfer-mock","messages":[{"role":"system","content":"be brief"},{"role":"user","content":"write a haiku about GPUs"}],"max_tokens":16,"seed":1}'
```

```json
{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "created": 1792512960,
  "model": "tinyinfer-mock",
  "choices": [{
    "index": 0,
    "message": {"role": "assistant", "content": "echo: system be brief ..."},
    "logprobs": null,
    "finish_reason": "length"
  }],
  "usage": {"prompt_tokens": 9, "completion_tokens": 16, "total_tokens": 25}
}
```

- `id` 前缀为 `chatcmpl-`，`object` 固定 `chat.completion`。
- `choices[0].message` 至少含 `role` 与 `content`；命中 tool 回显时 `content` 为 `null` 并出现 `tool_calls`。

### 5.3 流式

- 帧结构与 4.3 相同，但 `object` 是 `chat.completion.chunk`，增量放在 `choices[0].delta` 里。
- 第一帧 `delta` 为 `{"role":"assistant","content":""}`，之后每帧为 `{"content":"<片段>"}`。
- 结束帧 `delta` 为空对象 `{}`，`finish_reason` 有值。
- `include_usage` 为真时，结束帧之后追加一帧 `choices: []` + `usage`。

OpenAI Python SDK：

```python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="dummy")
resp = client.chat.completions.create(
    model="tinyinfer-mock",
    messages=[{"role": "user", "content": "hello tinyinfer"}],
    max_tokens=16,
    temperature=0.7,
)
print(resp.choices[0].message.content)
print(resp.usage)

stream = client.chat.completions.create(
    model="tinyinfer-mock",
    messages=[{"role": "user", "content": "stream, please"}],
    max_tokens=32,
    stream=True,
    stream_options={"include_usage": True},
)
for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
    if chunk.usage:
        print("\nusage:", chunk.usage)
```

不装 SDK 时直接用 httpx 解析 SSE：

```python
import json, httpx

with httpx.Client(base_url="http://127.0.0.1:8000/v1", timeout=600) as c:
    with c.stream("POST", "/chat/completions", json={
        "messages": [{"role": "user", "content": "hello"}],
        "max_tokens": 8,
        "stream": True,
    }) as r:
        for line in r.iter_lines():
            if not line.startswith("data: "):
                continue
            payload = line[6:]
            if payload == "[DONE]":
                break
            chunk = json.loads(payload)
            if chunk.get("choices") and chunk["choices"][0]["delta"].get("content"):
                print(chunk["choices"][0]["delta"]["content"], end="", flush=True)
```

### 5.4 最小 function calling（tools 回显）

`tools` / `tool_choice` 是最小实现：**不执行工具**，只从模型输出里识别一次函数调用，回显成 OpenAI 的 `tool_calls`，
让 agent 客户端拿到可解析的结果。识别格式（任一即可）：

- 纯 JSON：`{"name": "lookup", "arguments": {"q": "x"}}`
- 代码块：`json` 围栏包裹的同一 JSON
- 包装：`<tool_call>{...}</tool_call>`

规则：

- 只有请求声明了 `tools`、模型写出了合法 JSON、且函数名在 `tools[].function.name` 中才识别；
  名字不匹配或 JSON 不合法时，原文按普通 `content` 返回，不会误吞内容。
- 参数取 `arguments` 键，缺失时取 `parameters`；对象会被序列化成 JSON 字符串。
- 非流式：`message.content` 为 `null`，`message.tool_calls=[{id, type:"function", function:{name, arguments}}]`，
  `finish_reason="tool_calls"`，`id` 形如 `call_<hex>`。
- 流式：声明了 `tools` 时服务端会缓冲完整输出（要拿到完整 JSON 才能判定），生成结束后一次性发一个
  `tool_calls` delta 和结束帧；未命中则把整段文本作为单个 `content` delta 发出，此场景不逐 token 流式。
- `tool_choice: "none"` 关闭识别。

```powershell
curl.exe http://127.0.0.1:8000/v1/chat/completions `
  -H "Content-Type: application/json" `
  -d '{"messages":[{"role":"user","content":"find tinyinfer"}],"tools":[{"type":"function","function":{"name":"lookup","parameters":{"type":"object"}}}],"max_tokens":64}'
```

```json
{
  "choices": [{
    "index": 0,
    "message": {
      "role": "assistant",
      "content": null,
      "tool_calls": [{
        "id": "call_ab12...",
        "type": "function",
        "function": {"name": "lookup", "arguments": "{\"q\": \"tinyinfer\"}"}
      }]
    },
    "finish_reason": "tool_calls"
  }],
  "usage": {"prompt_tokens": 8, "completion_tokens": 12, "total_tokens": 20}
}
```

协议层回显，模型本身没有工具执行能力；真正的结构化输出和工具循环由上层 agent 负责。

## 6. 会话、槽位与并发

tinyinfer 把一条对话的 KV 缓存 / 专家缓存归到一个**槽位（slot）**，HTTP 层只负责把请求路由到槽位并把元数据暴露出来，
多个 agent 并发时不会互相污染缓存。

- 会话 id 取自请求体 `session_id`，其次取请求头 `X-Session-Id`（请求体优先）。
- `session_id` 只允许 1–128 个 `[A-Za-z0-9._:-]` 字符，超长或含其它字符返回 400 `invalid_session_id`。
- 同一个 `session_id` 的请求复用同一槽位，必须顺序发；同一会话并发请求返回 429 `session_busy`。
- 不带 `session_id` 的请求取一个临时槽位，用完即释放，适合一次性调用（分类、探测）。每次取用前会重置该槽的缓存。
- 槽位占满时按 LRU 淘汰空闲会话；没有可淘汰的返回 429 `server_busy`。
- 并发上限由 `--max-concurrency` 控制，超过立即返回 429 `rate_limit_exceeded`，**不排队**。上述三种 429 都带 `Retry-After: 1`。

### 6.1 槽位状态

```powershell
curl.exe http://127.0.0.1:8000/v1/slots
```

```json
{
  "object": "list",
  "total_slots": 4,
  "busy_slots": 0,
  "sessions": 1,
  "slots": [
    {"id_slot": 0, "session_id": "agent-a", "busy": false, "n_ctx": 1048576,
     "n_prompt_tokens": 12, "n_completion_tokens": 8, "requests": 2},
    {"id_slot": 1, "session_id": null, "busy": false, "n_ctx": 1048576,
     "n_prompt_tokens": 0, "n_completion_tokens": 0, "requests": 0}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `total_slots` / `busy_slots` / `sessions` | 槽位总数 / 正在服务的槽位数 / 绑定中的会话数 |
| `slots[].id_slot` | 槽位编号 |
| `slots[].session_id` | 绑定到该槽的会话 id，临时槽位为 `null` |
| `slots[].busy` | 是否有请求正在占用 |
| `slots[].n_ctx` | 该槽位的上下文上限 |
| `slots[].n_prompt_tokens` / `n_completion_tokens` | 该槽位最近一次请求的 prompt 与生成 token 数 |
| `slots[].requests` | 该槽位累计处理过的请求数 |

### 6.2 超时

单请求超时由 `--request-timeout` 控制（默认 600 秒），从请求开始计时。

- 非流式：返回 504 `timeout`。
- 流式：HTTP 状态已是 200，改为发一帧 error 后再 `[DONE]`，见 8.3。

## 7. 模型与路由

### 7.1 `/v1/models` 字段

```json
{
  "object": "list",
  "data": [
    {
      "id": "deepseek-v41-l0",
      "object": "model",
      "created": 1792512960,
      "owned_by": "tinyinfer",
      "context_length": 1048576,
      "max_output_tokens": 1048576,
      "adapter": "deepseek_v41_hf",
      "tier": "conservative",
      "layers": [0],
      "model_dir": "D:\\weights\\deepseek-v41",
      "loaded": true,
      "supported": true
    },
    {
      "id": "gguf-future",
      "adapter": "gguf",
      "loaded": false,
      "supported": false,
      "note": "GGUF adapter is reserved (see tinyinfer.adapters.open_adapter)"
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `id` / `object` / `created` / `owned_by` | 模型 id、固定 `model`、创建时间（Unix 秒）、固定 `tinyinfer` |
| `context_length` | 该模型的上下文上限；未提供时取 `--max-context-tokens` |
| `max_output_tokens` | 单次输出上限，等于 `--max-tokens-limit` |
| `adapter` | 检测到的 checkpoint 布局，见 7.3 |
| `tier` | 该模型的优化档位 |
| `layers` | 加载的层号列表；全部加载时为 `null` |
| `model_dir` | 权重目录 |
| `loaded` | 后端是否已实际加载该模型（懒加载，首次请求前为 `false`） |
| `supported` | 当前代码能否服务该模型；`false` 时请求会失败并带 `note` 说明原因 |
| `note` | `supported` 为 `false` 时的原因说明 |
| `alias_of` / `aliases` | 别名条目会单独出现在列表里，用 `alias_of` 指回主 id；主条目用 `aliases` 列出全部别名 |

### 7.2 路由规则

没有额外的路由端点：同一个应用里，后端按请求的 `model` 字段分发。

- `model` 精确匹配注册 id 或其别名 → 用该模型的后端，按需懒加载。
- 未知名字（例如 agent 配置里的 `gpt-4o` / `deepseek-chat`）→ 落到 `--default-model`，响应里的 `model` 仍回显请求名。
- 请求不带 `model` → 用后端默认模型的 id。

```powershell
.\tinyinfer\.venv\Scripts\python.exe -m tinyinfer.server `
  --backend tiny `
  --model-dir D:\weights\deepseek-v41 --layers 0 --model-id deepseek-v41-l0 `
  --extra-model gguf-future=D:\weights\future-gguf `
  --tier conservative --default-model deepseek-v41-l0
```

### 7.3 adapter 与支持状态

| adapter | 触发条件 | 行为 |
|---|---|---|
| `hf_deepseek_v41` | 目录里有 `model.safetensors.index.json` | 可服务，`supported: true` |
| `gguf` | 目录里有 `*.gguf` | 预留；请求返回 501 `adapter_not_implemented`，`/v1/models` 标 `supported: false` 并带 `note` |
| 其它 / 未识别 | 上面两条都不匹配 | 请求返回 501 `adapter_not_supported` |
| 权重或分词器缺失 | — | 503 `model_not_loaded` / `tokenizer_load_failed` |

## 8. 错误

### 8.1 错误对象

所有错误都是 OpenAI 的 error object：

```json
{
  "error": {
    "message": "Invalid request: body.messages: List should have at least 1 item after validation, not 0",
    "type": "invalid_request_error",
    "param": "messages",
    "code": "invalid_request"
  }
}
```

`param` 指明出错的字段（无具体字段时为 `null`），`code` 是稳定标识，客户端应当按 `code` 分支处理而不是匹配 `message`。

### 8.2 错误码

| HTTP | code | 场景 |
|---|---|---|
| 400 | `invalid_request` | 参数缺失或非法：`temperature` 越界、`n>1`、`stop` 超 4 个或为空串、消息角色非法、多元素 prompt 列表、非文本内容分片等 |
| 400 | `context_length_exceeded` | prompt 加 `max_tokens` 超出上下文；开启 `--fit-max-tokens` 时会自动压缩而不是报错 |
| 400 | `invalid_session_id` | `session_id` 含非法字符或长度不符 |
| 401 | `invalid_api_key` | 没带或带错 API key（响应含 `WWW-Authenticate: Bearer`） |
| 404 | `not_found` | 未知路径 |
| 404 | `model_not_found` | `/v1/models/{id}` 的模型不存在 |
| 405 | `method_not_allowed` | 方法不正确 |
| 429 | `rate_limit_exceeded` | 并发超过 `--max-concurrency` |
| 429 | `server_busy` | 槽位全忙，且没有可淘汰的空闲会话 |
| 429 | `session_busy` | 同一 `session_id` 已有请求在跑 |
| 500 | `internal_error` | 未捕获的服务端异常 |
| 500 | `backend_error` | 后端拒绝服务且未给出更具体的信息 |
| 501 | `not_implemented_error` | `/v1/messages`、`/v1/messages/count_tokens`（Anthropic 预留） |
| 501 | `adapter_not_implemented` | GGUF 等预留 adapter |
| 501 | `adapter_not_supported` | 无法识别的 checkpoint 布局 |
| 503 | `model_not_loaded` | 权重未就绪（目录不对、分片没下完） |
| 503 | `tokenizer_load_failed` | 分词器加载失败 |
| 504 | `timeout` | 超过 `--request-timeout` |

### 8.3 流式错误帧

流式请求一旦开始（HTTP 200），中途出错改用 SSE 上报，之后照常 `[DONE]` 收尾：

```text
data: {"error":{"message":"...","type":"timeout_error","param":null,"code":"timeout"}}

data: [DONE]
```

- 后端报错时 `code` / `type` 沿用后端的值（如 `timeout` / `timeout_error`）。
- 后端抛出的其他异常统一为 `code: "stream_error"`、`type: "server_error"`。
- 收到 error 帧后不应再期待 usage 帧。

### 8.4 按错误码排查

- **401 `invalid_api_key`**：服务端配了 `--api-key`，客户端要带 `Authorization: Bearer <key>`；`/health` 不需要。
- **429 `rate_limit_exceeded`**：`--max-concurrency` 偏小，或上一个请求还没结束；调大它，或按 `Retry-After` 等待。
- **429 `server_busy` / `session_busy`**：槽位全忙 / 同一 `session_id` 并发；调大 `--max-slots`，或让不同 agent 用不同 `session_id`。
- **503 `model_not_loaded`**：`--backend tiny` 但 `--model-dir` 不对、分片没下完，或先启动后下载。
- **504 `timeout`**：预填或解码超过 `--request-timeout`；大 prompt 或慢机器上调大（默认 600 秒）。
- **501 `adapter_not_implemented` / `adapter_not_supported`**：checkpoint 是 GGUF 或布局无法识别；换成 HF safetensors（目录里需要
  `config.json` + `model.safetensors.index.json`），或先看 `/v1/models` 里的 `supported` 与 `note`。
- **连接成功但没有输出**：看 `/health` 的 `ready` 和后端日志；长 prompt 期间只有 `: keep-alive` 注释，属正常。

## 9. 上下文、token 与已知限制

### 9.1 上下文与输出

- 上下文默认 **1,048,576 token（1M）**，输出上限默认同样是 1M，都由启动参数控制；单个模型可通过 `context_length` 收窄。
- 请求进来先由后端 `count_prompt_tokens` 计数，再检查 `prompt + max_tokens <= 上下文`：
  超了返回 400 `context_length_exceeded`；开启 `--fit-max-tokens` 时把 `max_tokens` 压到剩余空间（剩余不足 1 时仍报错）。
- `prompt` 本身就等于或超过上下文时，`--fit-max-tokens` 也救不回来，仍返回 400。
- `stop` 最多 4 个，命中后 `finish_reason` 为 `stop`，stop 文本本身不返回；stop 可以跨 token 边界。
- `prompt` 为空字符串是允许的；列表形态只支持单元素。

### 9.2 usage

usage 取后端终态事件上报的值；缺失时服务端用 `prompt_tokens` 加上实际流出的 token 数兜底。
非流式响应必带 usage；流式只在 `stream_options.include_usage` 为真时，在结束帧后追加一帧。

### 9.3 已知限制

| 能力 | 状态 |
|---|---|
| `/v1/models`、`/v1/completions`、`/v1/chat/completions` | 支持 |
| 流式 SSE + `[DONE]` + keep-alive | 支持 |
| `temperature` / `top_p` / `top_k` / `seed` / `stop` | 支持 |
| `max_completion_tokens` 别名、`stream_options.include_usage` | 支持 |
| 多 API key、request id、统一错误对象 | 支持 |
| 会话 / 槽位隔离（每槽一份 KV 快照 + `reset_slot`） | 支持 |
| 多模型路由、动态 `/v1/models` | 支持 |
| `tools` / `tool_choice` 最小回显 | 支持，但缓冲输出、不执行工具 |
| `n>1`、多元素 prompt 列表 | 不支持，返回 400 |
| `logprobs`、`echo`、`suffix`、`user`、`response_format` | 接受但忽略 |
| 图片等非文本输入 | 不支持，返回 400 |
| Anthropic `/v1/messages` | 501 预留 |
| OpenAI `/v1/responses` | 未实现 |
| GGUF adapter | 501 预留 |
| 并发生成 | 同一后端内生成串行；并发能力靠多槽位与多模型撑 |

- OpenAI 语义是每次请求携带完整对话，客户端不需要自己维护增量历史。
- `tools` 场景下流式不逐 token 出字：服务端需要完整文本才能判定是不是一次函数调用；不声明 `tools` 时仍然逐 token 流式。

## 10. 后端约定（实现侧）

HTTP 层只依赖下面这份协议，换引擎只需实现它：

```python
class Backend(Protocol):
    model_id: str
    aliases: tuple[str, ...]
    def generate(self, request: GenerationRequest) -> Iterator[TokenEvent]: ...
    def count_prompt_tokens(self, request: GenerationRequest) -> int: ...
    def count_tokens(self, text: str) -> int: ...
    def render_prompt(self, request: GenerationRequest) -> str: ...
    def reset_slot(self, slot_id: int) -> None: ...
    def health(self) -> dict: ...
    def warmup(self) -> None: ...
    def close(self) -> None: ...
```

- `GenerationRequest` 携带 `request_id`、`prompt` 或 `messages`、`sampling`（`max_tokens` / `temperature` / `top_p` / `top_k` /
  `presence_penalty` / `repetition_penalty` / `stop` / `seed`）、`stream`、`session_id`、`slot_id`、`model`、
  以及服务端算好的 `prompt_tokens` 与 `deadline`。
- `slot_id` 是该请求的 KV / 专家缓存归属；新会话占用槽位时服务端会先调 `reset_slot` 丢掉旧状态，不同槽位互不覆盖。
- `generate` 逐个产出 `TokenEvent(text=...)`，最后一个事件的 `finish_reason` 只允许 `stop` 或 `length`，并可带 `usage`。
- `count_prompt_tokens` 必须与服务端后续计算使用的口径一致，否则 `context_length_exceeded` 的判定会和实际不符。
- 后端可以抛 `BackendError(message, status_code=..., error_type=..., code=...)`，服务端会原样翻译成 OpenAI 错误对象。
- 槽位数量由启动参数 `--max-slots` 决定，后端只按服务端分配好的 `slot_id` 归属缓存。
