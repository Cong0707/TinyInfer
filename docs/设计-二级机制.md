# 设计：二级机制

## 档位定义

| 档位 | 内容 |
| --- | --- |
| 0 | 纯 PyTorch 参考实现 |
| 1 | 已验证的移植（官方 kernel + NVIDIA Flare 的机制） |
| 2 | 本引擎自有的机制（**默认档**） |
| 3 | 近似算法（允许数值上偏离参考） |

装不下全部层的机器在档位低于 2 时**拒绝启动**，并给出明确信息：层 streaming 与专家
缓存属于引擎（二级）能力，不是可选项。

## 已实现的二级机制

### 张量并行（端到端）

`tp.py` 提供 `Shard.columns/rows`、`shard_linear`（切分量化投影时不破坏 fp8 的
128×128 与 fp4 的 32×32 分块边界）和 `all_reduce_sum`。

- 两类注意力都实现了 `_shard_for_tp`：q_lora 输出切片、`q_norm` 跟着切、头数切分、
  sink 切片、`wo_a` 的分组矩阵在 o_lora 维切、`wo_b` 在输入维切并在其后再做一次
  全归约。
- `wkv` 保持复制而不切分：本模型只有一个 KV 头，切它需要换一种注意力布局；官方
  Flare 的 QSA 也是复制。
- `MoE` 走专家并行：每张卡只服务自己拥有的专家，共享专家只在 rank 0 上算，部分输出
  最后求和一次。
- `tp_ranks == 1` 时所有路径逐字节不变。

### KV 窗口预分配

两类注意力原先每 token 都对 KV 历史做 `torch.cat` 再加 `.contiguous()`——每层每
token 一次新分配，而这正是挡住 CUDA graph 捕获的东西。现在改成在预分配缓冲里移位与
追加、对外交视图；压缩 KV 的分组缓冲也按 decode 尺寸预分配。这是图的前置条件，顺带
也消掉了每 token 数十次分配。

### 调度器即时间片选择

`scheduler.py`：请求表 + EEVDF 风格的虚拟时间。等过一个时间片的解码流优先，
时间片大小按「每秒有效工作量 / 已备容量」选。它不分配任何显存。

### 专家异步流水

门控一算完就下单读盘，不等 kernel 需要数据。GPU 主动提出缺失表，CPU 异步接收并准备
数据，用之前再等那一个事件。

### 容量驱动的派生缓存

反量化后的权重、rope 表这类「由其它张量算出来的常驻张量」统一走
`derived_cache.py`，容量由规划器给。不能每层一个 dict——那样会把几 GB 的 bf16
钉死在显存里。

## 二级机制必须满足的条件

1. **要么成立，要么明确失败。** 不允许「失败后静默退化到慢路径」，因为那样连「机制
   从来没生效过」都看不出来。
2. **有对拍。** 数值相关的机制要与参考实现比，并在 `kcheck/` 里留下用例。
3. **不引入第二条路径。** 例如专家必须走槽位，不能同时存在「走槽位」和「不走槽位」。
