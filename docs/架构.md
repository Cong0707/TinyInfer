# 架构

## 一次推理的数据流

    token ids ──> embed（权重表）──> [按 hc_mult 展开] ──> 40 个 Block ──> 折叠 ──> head ──> logits

每个 Block 内部：

    hc_mixes ─> attn_norm ─> MLA（窗口 / 压缩）─> hc_post
             ─> hc_mixes ─> ffn_norm  ─> MoE          ─> hc_post

Hyper-Connections（hc）把残差流维护成 hc_mult 份并行副本，每次进子层前用 Sinkhorn
算出一组混合权重，出子层后再加权写回。这是模型结构的一部分，不是优化技巧。

## 权重驻留模型

显存装不下全部层时，尾部若干层走 streaming：

1. 启动时按 streamed 层各建一块 pinned 主机内存，设备侧建若干环形缓冲槽。
2. 每层把整块权重拷进一个环槽，层内所有权重属性指向该槽的视图；拷贝在独立
   copy stream 上做，计算流等待它的 event。
3. 常驻层留在设备上，只有尾部逐 token 拷贝。**留几层是规划器解出来的，不是常量。**

不变量：每个权重属性要么是真张量（常驻或 CPU），要么是活动环槽的视图。
`reset()` 把 streamed 层指回 CPU 源但保留环，所以不会有悬空视图。

拷贝路径有两条：主机内存连续时一层一次扁平 H2D；Windows 上 cudaHostAlloc 把页散在
很大的地址空间里，只能逐张量 copy_，一层 28 次 DMA。字节数相同，launch 更多。

## 专家路径

- 门控在设备上算出路由，用 bincount 得到本层去重后的专家列表。
- `ExpertStore.fetch_async` 在门控之后立刻在盘读线程池上下单；`fetch` 等这些 future，
  然后拷进显存槽，或留在内存缓存里走零拷贝。
- 内存缓存按 blob 做淘汰策略。容量由规划器给，不由常量决定。
- 执行循环把 `y[idx] += w * expert(x)` 累积成一次 scatter，而不是逐专家累加。

**显存槽位是唯一路径。** 专家要么在槽位里被 kernel 直接寻址，要么通过缺失表被搬进
槽位。没有「不走槽位」的第二条路。

## 会话

`generate()` 以 `reset()` 开始：清路由记忆、逐层注意力状态、compressor/indexer、
专家缓存、共享 handoff 槽上的每次 forward 缓存。权重与缓存本身保持热。

## 决策方式

引擎里没有「if 24GB then ...」这种硬件表。每个决策都是从这台机器的实测可用显存、
内存、盘速解出来的：常驻层数、槽位数量、环形缓冲大小、prefill chunk、缓存配额。
规划结果在启动时打印一行，可以直接核对该机器上的取值。
