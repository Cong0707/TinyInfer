## 追到 MoE（L2）

```
ffn in:  p9 = 0.594     正常
ffn out: p9 = 868.000   <- 只有 p9
         p8 = 0.214     正常
         p10 = 0.297    正常
```

**只有第 9 行一个位置的 MoE 输出是 868，相邻的 p8 / p10 完全正常。**

## 结构因素

`xf.size(0) = 11` 行，`_forward_gpu_only` 按 3 行一批切成 **3+3+3+2** 四批。
**p9 是第四批的第一行**（行 9、10），p10 是第四批第二行 —— 同一批里 p9 坏、p10 好。

## 已排除

- `compress_kv`：组 0-5 全部 finite，组 5 是 0（未写，正确）
- attention 输出：p9 = 6.094（全批 absmax 7.688），正常
- `hc_post#1`：p9 = 1.445，正常
- `ffn` 输入：p9 = 0.594，正常
- 分批的 `_cat.view(...)` 形状：`x.shape[:-1] = (1,11)`，`_cat` 是 (11,5120)，对得上

## 探针本身撞到的另一个问题

`moe.forward(row)` 传入**单行**（1×5120）直接 `illegal memory access`
（`cuMemcpyHtoDAsync_v2` 返回 700）。这说明 `moe.forward` 对 1 行输入有独立缺陷，
和 p9 的问题可能是同一个（都是行数边界）。

## 下一个探针

不让 MoE 分批：把 `xf.size(0) > 3` 的阈值临时调大（或直接传 4 行、5 行），
看 p9 的异常是否随批次边界移动。如果 4 行一次跑完就正常，就锁定分批逻辑。
