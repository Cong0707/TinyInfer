# 快速开始

## 0. 安装

    .\scripts\bootstrap.ps1          # Windows
    ./scripts/bootstrap.sh            # Linux / macOS

它会建 venv、按你的 CUDA 驱动装 torch、把包装成 editable，**并编译 kernel**。

编译这一步决定速度：引擎所有 kernel 都从 `kernels/build/*.cubin` 加载，缺了就会退回
torch 实现，慢 5~10 倍。没有 `nvcc` 只是警告，退回的路径是正确的，只是慢。

改过某个 `.cu` 之后只重编那一个：

    .\scripts\build_native.ps1 -Only rms_norm      # Windows
    ./scripts/build_native.sh rms_norm              # Linux / macOS

前置条件：

- Python 3.12 以上
- Windows 上编译 kernel 需要 CUDA toolkit 与 VS Build Tools
- checkpoint 以 HF safetensors 形式放在快盘上。**盘的读速直接决定 decode 速度。**
- 8GB 卡上需要约 16GB 空闲主机内存给 pinned 层块

## 1. 生成一段文本

    python -m tinyinfer.cli generate \
        --backend tiny --model-dir /path/to/DeepSeek-V4.1-Flash \
        "中国的首都是" --max-tokens 16

或者从 Python 调：

    from transformers import AutoTokenizer
    from tinyinfer.engine import Engine
    tok = AutoTokenizer.from_pretrained(MODEL, trust_remote_code=True)
    eng = Engine(MODEL, tier=OptLevel.AGGRESSIVE, device="cuda", tokenizer=tok)
    ids = tok.encode("<｜begin▁of▁sentence｜><｜User｜>中国的首都是<｜Assistant｜></think>")
    print(tok.decode(eng.generate(torch.tensor([ids]), max_new_tokens=16)))

**prompt 必须按官方格式编码。** 这个 checkpoint 的 tokenizer 不带 chat template，
`apply_chat_template()` 会失败；直接喂裸文本模型只会续写，不会回答。正确格式是：

    <｜begin▁of▁sentence｜><｜User｜>问题<｜Assistant｜></think>回答

`tinyinfer.chat.encode_messages()` 就是这个编码器的实现，直接用它，不要手拼。

## 2. 起服务

    python -m tinyinfer.cli serve --backend tiny --model-dir /path/to/ckpt --port 8000

兼容 OpenAI 的接口：`/v1/models`、`/v1/completions`、`/v1/chat/completions`、
`/health`，支持 SSE 流式。细节见 [接口.md](接口.md)。

## 3. 看它规划成了什么

启动会打印一行规划结果：

    [tinyinfer] <卡型号> vram=..GB ram=..GB -> layers=40/40 stream=0 buf=0
                slots=1057 cache=274.3GB chunk=132 embed=gpu head=gpu

`layers=常驻层数/总层数`、`stream=走 streaming 的层数`、`slots=专家槽位数`、
`chunk=prefill 分块`。这些数字都是这台机器上解出来的，换机器会变。

## 4. 跑基准

    python -m tinyinfer.bench --model-dir /path/to/ckpt

输出 build / prefill / decode / cache / disk 五组数，JSON 格式，便于对比两次改动。

## 卡住了

- **输出是乱码或复读**：先确认 prompt 用了上面的官方格式；再确认 kernel 编译成功
  （缺 cubin 会退回 torch，数值正确但慢，不会乱码）。
- **`cuModuleLoad 209`**：cubin 是按别的架构编的。重新跑一次构建脚本。
- **显存不够**：规划器会自己降常驻层数。想强制指定用 `TI_GPU_LAYERS`，见
  [环境.md](环境.md)。
- **decode 很慢且 GPU 空转**：说明时间花在等盘上。看启动那行里的 `cache=` 是否够装
  下全部专家。
