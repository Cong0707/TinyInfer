# 模型结构

DeepSeek-V4.1-Flash。本文件只描述结构规格与由此推出的约束，不含实测数字。

## 主干

| 项 | 值 |
| --- | --- |
| 层数 | 40 |
| 隐藏维 dim | 5120 |
| 注意力头数 | 64 |
| head_dim | 512 |
| rope_head_dim | 64 |
| q_lora_rank | 1280 |
| o_groups / o_lora_rank | 8 / 1024 |
| 词表 | 129280 |

每层的结构：

    hc_mixes -> attn_norm -> MLA -> hc_post -> hc_mixes -> ffn_norm -> MoE -> hc_post

## Hyper-Connections

残差流不是一条，是 **hc_mult = 4** 份并行副本。每个子层前后各做一次混合：

- 进子层前用 Sinkhorn 归一化算出一组 `[hc, hc]` 的混合矩阵和两条 `[hc]` 的权重；
- 出子层后按这组权重把子层输出写回 4 条残差。

因此 Block 内部的张量形状是 `[b, s, hc, dim]` 而不是 `[b, s, dim]`。任何按
`[b, s, dim]` 写的探针或 kernel 都会读到错的维度。

## 注意力：两种层

40 层不是同构的，按 `compress_ratios` 分成两类：

```
compress_ratios = [0, 0] + [2] * 18 + [1] * 20
```

- **ratio = 0**（前两层）：纯滑动窗口注意力，窗口 128。
- **ratio > 0**：滑动窗口 + 压缩 KV。压缩比 r 表示每 r 个 token 池化成一个 latent。

压缩 KV 由 **kv_source 层**产出，同组其它层直接读：

```
kv_source_layer_ids  = [2, 8, 14, 20]
index_source_layer_ids = [2, 8, 14, 20, 24, 28, 32, 36]
```

也就是说 2/8/14/20 这四层负责压缩自己的 KV 并发布，后面的层共用；indexer（选哪些
压缩组可见）由 index_source 层算，其余层复用。

**这条共享关系是所有压缩层 bug 的温床**：per-layer 状态如果按「共享槽」而不是按
层号存，两个 ratio 不同的层会撞 key，读到对方的中间量。

## 压缩层的两个位置语义

容易错，单独列出：

1. **写入压缩 KV 的起点** 是 `start_pos // ratio`。
2. **压缩 latent 的 RoPE 位置** 是 `start_pos + 1 - ratio`，不是
   `(start_pos // ratio) * ratio`。一个 latent 代表它那一组的第一个 token，所以它
   的位置是组末位置回退 ratio-1。

两者只在 `start_pos % ratio == ratio - 1` 时相等，decode 的每一步里有 ratio-1 步
都不相等。位置差 1 会让 RoPE 角度整体偏移。

## 可见范围

每条查询能看到的压缩组数 = `(start_pos + seqlen) // ratio`。超出这个范围的组号必须
置 -1（kernel 的空槽标记），否则会把「未来」的零向量当成真实 KV 参与注意力。

## 滑窗

窗口 128。位置 p 的 KV 存在 `p % 128` 这一格，历史永不搬运。窗口索引只依赖绝对
位置，与「历史被移动过多少」无关。

## MTP

主干之后另有若干 MTP 层（多 token 预测），用于投机解码。它们不在主干前向里跑，
只在开启推测时进入。是否会启用由规划器决定——它要占用显存。

## engram

layer 1 与 layer 14 带 engram 表（n-gram 查表后注入残差）。这两张表**按行从磁盘读，
从不整体映射进显存**。任何按层统计权重大小的代码都必须把它们排除，否则会把一张
近百 GB 的表算成「一层的大小」，规划器随即判定装不下并拒绝启动。
